A compiler that reads your data before it runs your pipeline

PrepLang is a small language for cleaning tables and images before machine learning. Its compiler opens the real data while it compiles, so it can stop mistakes before anything runs, prove your checks, remove work that does nothing, and now carry those proofs to next month's data.

Everything on this page is real

Each program, error message, timing and number below was produced by running the compiler, the generated programs, the Phase 2 compiler and a plain pandas/OpenCV script on this project's data (demo/capture.py).

03

      
Every EXPECT gets a verdict before the program runs

      
Because the compiler knows the facts about each column at each line, a contract is proven, violated, or left as a run-time check.

      
SayProven contracts cost nothing at run time. Violated ones stop compilation and name the row. Only the undecidable ones become checks, and after the check passes the compiler uses the fact.

05

      
Data certificates: compile once, run safely on new data

      
After optimizing, the compiler analyses the program again with weaker facts, one at a time, and keeps only the facts some proof needs. The data had marks from 35 to 95; the program only needs 0 to 100. Edit the batch below and watch three policies decide.

      
SayThe fingerprint refuses any change. A schema of the old file's facts refuses marks of 12 or 100. The certificate only asks for what the proofs use, and when it refuses, it names the row and the proof.

06

      
Certificates for image folders

      
An image folder is certified as one box per file type: channel counts, width and height ranges, bit depths. The analysis checks the box through its corner images; the generated program reads only the header of each new image.

      
SayThe program has EXPECT MIN_WIDTH 200, so the certificate asks for width at least 200 and allows any height and channels. A new folder of different photos is admitted; one 150-pixel-wide photo is refused.

What the testing caught in my own compiler

      
Comparing every run against a fresh compilation, or against the script, exposed five bugs. All are fixed and each has a regression test.

    

    
    
      
  1. The run-time MATCH_RATE check counted broken images that REMOVE_CORRUPT had removed before the LINK.
    2. 
      
  2. The first certificate covered only loaded columns, so a proven NOT_NULL on a column pruned afterwards was unprotected.
    3. 
      
  3. Admission let whole numbers into a FLOAT column and an empty column into any type; a fresh compilation then decided differently.
    4. 
      
  4. A column named only by a DROP the optimizer had removed was treated as optional (found on held-out GitHub scripts).

  5. The pandas front end translated drop(columns=..., axis=1), which pandas itself rejects.

One-line summary

        
PrepLang reads the data at compile time, proves or refutes the data contracts, removes useless work, and writes a certificate of the few facts its proofs need, so one compiled program can safely clean next month's data, image folders and existing pandas scripts.
