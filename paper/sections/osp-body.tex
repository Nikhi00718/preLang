\section{Motivation and significance}

Data preparation makes assumptions that are often absent from a script's interface: a column contains
numbers, a value lies within a range, or an image operation preserves a usable output type. Such
assumptions contribute to the maintenance cost of machine-learning systems~\cite{sculley2015}.
A pandas~\cite{mckinney2010} or OpenCV~\cite{bradski2000} script may discover a violation only after
processing has started. Validators such as TFDV~\cite{breck2019}, Deequ~\cite{schelter2018}, Great
Expectations~\cite{gx} and pandera~\cite{bantilan2020} check datasets against constraints. They do not,
by themselves, propagate those constraints through a program and generate guarded optimizations.

\PL~\cite{preplang2026} targets batch workflows in which a representative input is available before the
pipeline runs. Its compiler scans CSV values, reads Parquet metadata and inspects image headers, then
propagates an abstract description of the data through the program. A contract is proven, definitely
violated, or unresolved: proven checks can be removed, violations are diagnosed, and unresolved checks
remain in the generated program.

The complication is reuse. A check that is redundant for one batch may be necessary for the next.
For each speculative removal, \PL records an \emph{item certificate}, the input facts that justify it.
The generated program checks the certificates on later batches and restores an instruction when its
certificate fails. A separate \emph{admission certificate} holds requirements for which the program has
no fallback, such as an incompatible column type; failing it stops execution. A changed value range
therefore restores one check without recompiling the rest of the pipeline.

The underlying ideas have precedents (Table~\ref{tab:related}). Type providers derive types from external
data~\cite{petricek2016}; soft constraints use properties observed in a database for query
optimization~\cite{godfrey2001}; dynamic deoptimization restores execution when speculative assumptions
fail~\cite{holzle1992,barriere2021}; Tuplex compiles a common path from sampled data with fallbacks for
exceptions~\cite{spiegelberg2021}; and provenance-based screening runs a preparation pipeline to catch
issues such as train/test leakage~\cite{schelter2024screening}. \PL combines these ideas in a small
preparation language whose certificates track the value facts behind individual removals. It does not
claim to have introduced data-dependent optimization or deoptimization.

\section{Software description}

\subsection{Software architecture}

The C++17 compiler uses only the standard library and has seven phases: lexing, parsing, semantic
analysis, intermediate representation, optimization, certification and Python code generation
(Fig.~\ref{fig:arch}). Semantic analysis tracks types, missing values, numeric intervals and image
properties at each statement. Parquet analysis uses footer statistics and image analysis reads headers,
so some facts stay unknown and the relevant checks are kept. After optimization the certifier weakens
input facts and reanalyzes the program, without rereading the input, to find what each certificate must
contain. The output is one Python program, which checks admission and guards speculative removals with
\texttt{deopt(i)}, and a machine-readable \texttt{preplang\_contract.json}.

\input{figures/figure-arch}

The Lean~4 development~\cite{lean4} proves selective deoptimization correct for any sound, monotone
analysis, and establishes those assumptions for a core of numeric columns, missing values, interval
filters, null filling, addition and range/not-null contracts. The C++ compiler, its parsers, pandas and
OpenCV are outside the proof, as are joins, aggregation, dates and images; differential tests cover joins
and aggregation. The repository contains \TestCount{} C++ checks in \TestSuites{} suites, integration tests
and parser fuzz targets, run in CI on Windows, Ubuntu and macOS with sanitizers, a coverage gate and the
Lean build.

\subsection{Software functionalities}

A program loads CSV or Parquet tables, selects and derives columns, filters rows, fills or drops missing
values, joins on one key and aggregates groups. Contracts cover types, nullability, ranges, uniqueness and
references; image pipelines check channels and dimensions, link labels, resize and convert. Diagnostics
give a source location and, where available, a witness row and a hint. Optimization removes proven checks
and redundant operations, prunes unread columns and streams images; rewrites that may change the output
need \texttt{--approx}, and the exactness results here exclude them. Every phase can be printed, with an
execution plan and JSON diagnostics, and \texttt{PLOT} and \texttt{REPORT} chart a batch. A translator lifts
the supported prefix of a pandas script, and with \texttt{--facts} a program compiles from differentially
private facts released by a data owner, while run-time checks still read the real data. \PL installs with
\texttt{pip install .}; \texttt{README.md}, \texttt{LANGUAGE.md} and \texttt{ARCHITECTURE.md} document
installation, the language and the implementation.

\section{Illustrative examples}\label{sec:example}

Consider this program with the eight-row \texttt{examples/\allowbreak tabular/\allowbreak students.csv}:
\begin{lstlisting}
LOAD "students.csv" AS students;
EXPECT students.age NUMBER;
EXPECT students.marks BETWEEN 0 AND 100;
EXPECT students.name NOT_NULL;
FILTER students WHERE marks >= 50;
EXPECT students.marks BETWEEN 60 AND 100;
SAVE students AS "clean.csv";
\end{lstlisting}

The compiler proves the first three contracts. After the filter it knows only that marks lie in
$[50,95]$, so the last check remains at run time. The range and not-null checks are removed
speculatively. On a new batch containing a mark of 104, the generated program restores the line-3 check
and rejects the batch, as a fresh compilation does (there, during compilation). A batch within the
certificates runs with both checks removed; text in the numeric \texttt{age} column fails admission.
For images, \texttt{examples/\allowbreak images/\allowbreak linked.prep} scales pixels to $[0,1]$ and saves
arrays. Requesting PNG output for those floating-point pixels gives a compile-time type error before any
pixel is decoded; the equivalent OpenCV script writes almost-black images without an error.

\paragraph{Correctness and reuse}
Across four seeds, \DiffAll{} generated tabular programs were checked with and without optimization
against a separate Python interpreter that shares no compiler code. Agreement means the same output
values (within relative and absolute tolerances of $10^{-9}$) or the same failing contract. All agreed,
and no admitted reuse gave a wrong outcome (Table~\ref{tab:results}). Of the batches in which one numeric
column changed between integer and float, \DiffFlipRefused{} were refused. Most refusals are deliberate:
the type rule only relaxes columns that no \texttt{DERIVE}, join key or aggregate combines with another
column, and \DiffFlipRefusedCombined{} of the \DiffFlipRefusedCompiles{} refused batches that a fresh compilation
accepts changed such a combined column. The test shows that
admitted batches are handled correctly, not that admission accepts every safe batch.

Five authored pipelines use NYC green taxi, Citi Bike Jersey City, and UCI traffic, bike-sharing and
Beijing air-quality data. Each is compiled on the first month, or on the preceding month, and run on the
later ones: \RealRuns{} pipeline--batch trials, with target months repeated across the two schedules. All
agreed with fresh compilation, \RealFreshFails{} of them on a contract failure. Fresh compilation shares
the implementation under test, so this checks reuse consistency; the independent interpreter above checks
correctness.

\paragraph{Coverage and cost}
The translator lifts only supported prefixes, and the script corpora are tied to particular datasets, so
the coverage figures in Table~\ref{tab:results} do not describe Python programs in general. Speed is not
\PL's main benefit: on a synthetic 200{,}000-row table the optimized program took \TabOpt\,s against
\TabBase\,s for a script (median of three runs, including Python start-up, on an Intel Core i5-12450H
with Windows~11, pandas~3.0 and Python~3.14), and the census median speedup is \CenSpeedMed$\times$.
Compilation is paid once per pipeline, not per batch: admitting a later batch by its certificate changed
the run time by \OhPctLow\% to \OhPctHigh\%. The benefit lies in errors reported before data is processed
and in batches that run without recompilation, with removed checks restored only where needed.

The validators (Great Expectations~0.18.22, pandera~0.34, TFDV~1.21) were used as admission gates
inferred from the compiled batch. Their results measure those gates, not the tools' ability to enforce
hand-written contracts. With private facts at $\varepsilon=1$, compilation kept every removal in the taxi
and traffic pipelines but 14\% in the bike pipeline, against 54\% for the AIM-based
configuration~\cite{mckenna2022aim}; no output of \PrivRuns{} later runs disagreed with fresh compilation.

\paragraph{Reproduction}
The release in Table~\ref{tab:metadata} pins the compiler and the stored results.
\texttt{eval/\allowbreak reproduce.sh check} builds and tests the software and regenerates every number
from those results; \texttt{full} reruns the experiments, including all four seeds and both lifter
versions, and \texttt{baselines} the validators and private compilation. Kaggle inputs must be downloaded
by hand; the GitHub corpora are pinned by commit and hash.

\section{Conclusions}

\PL makes data assumptions explicit before a preparation pipeline runs and keeps the conditions behind
removed work when the compiled program is reused. Joins use one key, Python is the only backend, numeric
type changes are admitted only for uncombined columns, and the proof covers a restricted core; the
implementation is tested, not verified. Whether \PL pays off depends on whether a pipeline fits the
language and is run on many batches.

\section{Future plans}

Joins on several key columns, code generation for other targets, and a study with users who write
preparation scripts.
