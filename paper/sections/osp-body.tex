\section{Motivation and significance}

Data-preparation mistakes propagate silently into models~\cite{sculley2015}. A preparation
pipeline is usually a script over pandas~\cite{mckinney2010} and OpenCV~\cite{bradski2000} that cannot
know, until it runs, whether a column it normalizes holds numbers or whether the images it saves as PNG
hold float pixels; validators such as TFDV~\cite{breck2019}, Deequ~\cite{schelter2018}, Great
Expectations~\cite{gx} and pandera~\cite{bantilan2020} check the data separately from the code that
transforms it. \PL uses a property of batch preparation that compilers leave unused: the inputs exist
when the pipeline is compiled. As F\# type providers do for types~\cite{petricek2016}, but for values,
it reads every CSV cell, Parquet footer and image header, follows types, missing values, value ranges
and image properties through the pipeline, proves or refutes each contract before any data is
processed, and removes the checks and operations the data makes useless.

Such proofs hold for one file, while the pipeline runs again next month on a file with the same layout
and other values. \PL therefore computes, for every removal, the facts about the input it depends on
(its \emph{item certificate}), and the generated program checks them on each new batch: a removal whose
facts hold stays removed, one whose facts a batch breaks runs again (\emph{selective deoptimization},
from dynamic compilers~\cite{holzle1992,barriere2021}), and a batch is refused only for
facts no run-time code can stand in for, such as a changed column type. A user writes a \texttt{.prep}
program, compiles it against the current batch, reads the diagnostics and deploys the generated program
for every later batch. The theory (with its Lean proofs) and the full evaluation are documented in the
repository (\texttt{paper/}, \texttt{docs/}); this article describes the software.

Table~\ref{tab:related} places \PL among the closest tools. Validators know the values but check them
apart from the code and again on every batch; compile-time analyses follow the code but know only
declared or inferred structure. To our knowledge, no other tool both decides value contracts at
program points from the real data and carries those decisions safely to later batches.

\section{Software description}

\subsection{Software architecture}

The compiler (\texttt{src/}, about 11{,}800 lines of C++17 without external libraries) runs lexer, LL(1)
parser, semantic analysis, IR, optimizer, certifier and code generator in turn. The \emph{schema} readers
scan CSV files in parallel and read Parquet footers and PNG and JPEG headers; the \emph{semantic
analyzer} computes the abstract dataset state (types, missing values, value intervals, image properties)
and decides every contract; the \emph{optimizer} removes, speculatively, what the state shows to
have no effect; the \emph{certifier} re-runs the analysis under weakened input facts, reading no data, to
find the admission certificate and one item certificate per removal (Fig.~\ref{fig:arch}); the
\emph{back end} generates one Python program that admits a batch and guards every removed instruction
with \texttt{deopt(i)}, and writes the certificates to \texttt{preplang\_contract.json}.

\input{figures/figure-arch}

The repository also holds \texttt{proofs/} (\LeanLines{} lines of Lean~4~\cite{lean4}: selective
deoptimization is exact for any monotone and sound analysis, and the analysis of a core of the language is
sound and monotone), \texttt{tests/} (\TestCount{} checks in \TestSuites{} suites, with randomized soundness
tests), a lifter of pandas scripts (\texttt{frontend/}), the composition and release tools
(\texttt{tools/}), a local editor app (\texttt{studio/}) and the evaluation (\texttt{eval/}).

Continuous integration builds and tests the compiler on Windows (MSVC), Ubuntu and macOS (GCC), compiles
every example end to end, and runs the tests under AddressSanitizer and UndefinedBehaviorSanitizer, a
line-coverage gate, \texttt{clang-format} and \texttt{clang-tidy}, and libFuzzer on the three parts that
read untrusted bytes (the \texttt{.prep} front end, the CSV scanner and the Parquet footer reader); it also
checks the Lean proofs and builds the Docker image. Each release publishes compilers for the three
systems that need no C++ toolchain. \texttt{LANGUAGE.md} is the reference of the language, the command
line and the generated program.

\subsection{Software functionalities}

{\sloppy
\begin{itemize}
\item \textbf{Compile-time checking:} misspelled or removed columns, type errors and broken contracts
(\texttt{NOT\_NULL}, \texttt{BETWEEN}, \texttt{UNIQUE}, \texttt{REFERENCES}, schemas, image channels and
sizes, match rates of images and labels), lookup joins on keys of other types or with repeated values,
reported with the line, the offending row and a hint; groups (\texttt{AGGREGATE}) keep their facts.
\item \textbf{Data-driven optimization:} proven checks and no-effect operations are removed, unused
columns are not loaded, image pipelines are streamed; rewrites that change the output need
\texttt{--approx}.
\item \textbf{Reuse:} admission by certificate, and re-enabled removals with the reason printed.
\item \textbf{Beyond one program:} \texttt{tools/\allowbreak contracts.py} checks one compiled stage's
guarantees against the next stage's certificates; \texttt{frontend/\allowbreak pandas2prep.py} lifts the
cleaning part of pandas scripts into \PL; and with \texttt{--facts} a program compiles from differentially
private facts its data owner released (\texttt{tools/\allowbreak release\_facts.py}), opening no input
file, while every run stays exact.
\item \textbf{Inspection:} every phase can be printed (\texttt{--tokens} to \texttt{--python}), with an
execution plan (\texttt{--explain}) and the files a run would touch (\texttt{--dry-run}).
\end{itemize}
}

\section{Illustrative example}\label{sec:example}

\begin{lstlisting}
LOAD "students.csv" AS students;
EXPECT students.age NUMBER;
EXPECT students.marks BETWEEN 0 AND 100;
EXPECT students.name NOT_NULL;
FILTER students WHERE marks >= 50;
EXPECT students.marks BETWEEN 60 AND 100;
SAVE students AS "clean.csv";
\end{lstlisting}

Compiled against an eight-row \texttt{students.csv} (from \texttt{examples/\allowbreak tabular/}),
\PL proves the first three contracts and checks the fourth at run time, since after the filter it only
knows that the marks lie in $[50, 95]$. It removes the range and not-null checks speculatively, and
\texttt{--certificate} shows the facts the range check needs: marks at least 0 and at most 100. Run on a later batch in
which a mark is 104, the generated program re-enables the check and stops where a fresh compilation
would:
{\small\begin{verbatim}
Deoptimized line 3: EXPECT students.marks BETWEEN 0 AND 100:
  marks goes up to 104, above 100
ContractError: line 3: students.marks has values outside 0 to 100
\end{verbatim}}
\noindent A batch within the facts runs with both checks removed; a batch whose \texttt{age} holds text is
refused, since no generated code can stand in for the analysis of another type.

The same analysis covers images, from their headers alone. In \texttt{examples/\allowbreak images/\allowbreak
linked.prep}, images and their labels are linked and checked, resized, normalized to $[0, 1]$ and saved as
NumPy arrays. Changing the format to PNG gives, before any pixel is decoded:
{\small\begin{verbatim}
error[type]: cannot save FLOAT32 pixels as PNG:
             NORMALIZE at line 10 scaled them to [0, 1]
   --> examples/images/linked.prep:13:1
13 | SAVE_IMAGES imgs TO "processed/ml_ready/";
   = hint: image files store 8-bit pixels, so these would come out
     almost black; add CONVERT imgs TO NPY; to keep the float
     values
\end{verbatim}}
\noindent The equivalent hand-written OpenCV script runs without an error and writes almost black images.

\section{Impact}\label{sec:impact}

The evaluation in \texttt{eval/} answers six questions (\texttt{eval/\allowbreak evaluate.py} writes the
answers with every number below):

\begin{itemize}
\item \textbf{Correctness: is the output right?} \DiffPrograms{} random programs (with joins and
groups), compiled with and without the optimizer, agree cell by cell with a reference interpreter that
shares no code with the compiler, and reused on a second batch none of the \DiffReuse{} runs differs from
it; before two fixes this test led to (a pruning bug, a pandas~3 incompatibility), \DiffBeforeWrongOpt{}
optimized runs were wrong. Three more seeds (\DiffSeedPrograms{} programs) found one more bug (a statistic
fill removed as a dead store, though it can stop the program; \DiffSeedBeforeWrong{} wrong run), fixed with
a regression test, after which all \DiffSeedAgree{} agree and none of \DiffSeedReuse{} reuses is wrong. Reused on new batches, \PrivRuns{} runs after \PrivCompilations{} private
compilations and every run of the experiments below did what a fresh compilation does.
\item \textbf{Performance.} An optimized table pipeline runs in \TabProcOpt\,s instead of \TabProcOz\,s
after Python start-up, and an image pipeline as fast as a hand-written streaming script, in \ImgPlMem\,MiB
instead of the \ImgBaseMem\,MiB of a script that loads every image.
\item \textbf{Optimization effectiveness.} On \CenPrograms{} examples and lifted programs the optimizer
removes \CenInstrCut\% of the instructions, \CenChecksCut\% of the run-time checks and \CenColsCut\% of
the columns read, with identical output.
\item \textbf{Practical usefulness.} \RbEarly{} of \RbTotal{} real failures from GitHub issues are reported
before any data is processed; lifted pandas scripts from GitHub reproduce their results on new batches in
\CorpusBothSame{} of \CorpusBothRuns{} runs, and in all \DriftRuns{} monthly runs of \DriftCompiled{}
scripts written by others; on 16 million Parquet rows a misspelled column is reported in
\ScTabNamePl\,s instead of after \ScTabNameScript\,s.
\item \textbf{Comparison.} On \RealRuns{} real monthly batches the compiled programs handle
\RealDeoptCorrect{} (\RealDeoptCorrectPct\%) as a fresh compilation would, with \RealDeoptUnsound{} wrong;
Great Expectations and pandera refuse \RealValidatorStopMin--\RealValidatorStopMax\% of the months a fresh
compilation runs, and TFDV admits months on which the program then differs. All 24 injected mistakes are
reported at compile time, where a script-style program crashes on 20 and writes wrong output on 4.
From private facts at $\varepsilon=1$ the taxi and traffic pipelines keep every removal (fixed bins:
\PrivGenTaxiEpsOneRecall\%, \PrivGenTrafficEpsOneRecall\%); HDMM~\cite{mckenna2018hdmm} and
AIM~\cite{mckenna2022aim} do no better.
\item \textbf{Overhead.} Compiling takes a median of \CenCompileMed\,ms and at most \CenMemMax\,MiB
(\CenCsvMillionMem\,MiB for a million CSV rows, \CenPqSixteenMem\,MiB for a \CenPqSixteenSize\,MiB Parquet
file, of which only the footer is read); admitting a new batch changes run time by \OhPct\%.
\end{itemize}

\noindent \texttt{eval/\allowbreak reproduce.sh check} rebuilds the compiler, runs every test and regenerates
every number above from the committed results, without network access; \texttt{full} reruns the
experiments and \texttt{baselines} the validators and differential-privacy mechanisms, in pinned
environments (\texttt{eval/\allowbreak README.md}). The evaluation is reusable on its own: the differential
harness with its reference interpreter tests any change to the optimizer, and the GitHub script corpora
are frozen as evaluated, each file by its URL at a fixed commit and its hash (1{,}773 of the 1{,}778 files
could still be downloaded on 23 October 2026), so other validators and pipeline analyses can be compared
on the same programs and batches. \PL is a research prototype by one author, begun in a compiler-design
course; it has no users outside the author's experiments yet. Its abstract state, certifier and code
generator are separate modules that others can extend.

\section{Limitations and conclusions}

Joins are lookups on a key with one name in both tables (no many-to-many joins), groups have five
aggregates, and only Python is generated; a changed column type is refused rather than handled; the
mechanized proofs cover a core of the analysis without joins and groups, and the rest is tested; the
compiler is tested on Windows (MSVC), Ubuntu and macOS (GCC). Planned work is general joins, generated
code that adapts to type changes, and a Python package. \PL compiles a pipeline once and runs it on later batches
exactly as a fresh compilation would, re-enabling only the removals a batch makes unsafe.
